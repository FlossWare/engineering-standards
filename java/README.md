# Java Quality Tools Templates

Standardized Maven-based Java quality tool configurations for FlossWare projects.

## Templates Included

### Build Configuration
- `pom.xml.template` - Complete Maven POM with 24 plugins
  - Compiler, CheckStyle, SpotBugs, PMD, JaCoCo
  - Surefire/Failsafe (unit + integration tests)
  - Javadoc, Source, GPG signing
  - Versions, Enforcer, Dependency plugins

### Quality Configurations
- `checkstyle.xml` - Google Java Style Guide
- `spotbugs-exclude.xml` - SpotBugs exclusion rules
- `pmd-ruleset.xml` - PMD rule configuration

### CI/CD
- `.github/workflows/ci.yml.template` - Java CI matrix
  - Java 11, 17, 21
  - Ubuntu, macOS, Windows
  - Maven test + package + verify

## Quality Standards

- **Coverage**: JaCoCo 80% line, 70% branch minimum
- **Style**: Google Java Style (CheckStyle)
- **Bugs**: SpotBugs with FindSecurityBugs
- **Quality**: PMD with 200+ rules
- **Testing**: JUnit 5 + Mockito
- **Java Support**: 11, 17, 21 (compile target: 11)

## Maven Plugins

### Build & Compile
- maven-compiler-plugin: Java 11 target, UTF-8
- maven-jar-plugin: Manifest generation
- maven-source-plugin: Source JAR
- maven-javadoc-plugin: API docs (fail on warnings)

### Quality & Testing
- maven-checkstyle-plugin: Google Style validation
- spotbugs-maven-plugin: Bug detection + security
- maven-pmd-plugin: Code quality analysis
- jacoco-maven-plugin: Coverage (80%/70% gates)
- maven-surefire-plugin: Unit tests
- maven-failsafe-plugin: Integration tests

### Reporting
- maven-site-plugin: Project website
- maven-project-info-reports-plugin: Project reports

## Usage

```bash
# Copy to Java project
cp build-tools/java/pom.xml.template myproject/pom.xml
cp build-tools/java/*.xml myproject/

# Edit placeholders
sed -i 's/{{GROUP_ID}}/org.flossware/g' myproject/pom.xml
sed -i 's/{{ARTIFACT_ID}}/myproject/g' myproject/pom.xml
sed -i 's/{{VERSION}}/1.0.0-SNAPSHOT/g' myproject/pom.xml

# Run quality checks
mvn clean verify
```

## Version Format

FlossWare projects use **X.Y versioning** (not X.Y.Z):
- Maven examples: `1.0`, `1.1`, `2.0`
- Simpler version management
- Matches FlossWare build-tools standard (currently 2.0)

When using pom.xml.template:
```xml
<groupId>{{GROUP_ID}}</groupId>
<artifactId>{{ARTIFACT_ID}}</artifactId>
<version>{{VERSION}}</version>  <!-- Use X.Y format: "1.0", "2.0", etc. -->
```

Maven fully supports X.Y versions for releases and X.Y-SNAPSHOT for development.
