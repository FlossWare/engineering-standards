# Python Quality Tools Templates

This directory contains standardized Python quality tool configurations for FlossWare projects.

## Templates Included

### Core Configuration
- `pyproject.toml.template` - Modern PEP 517/518 build configuration with all tool settings
- `.pre-commit-config.yaml.template` - Pre-commit hooks (ruff, black, mypy, bandit)
- `.editorconfig` - Editor consistency settings

### CI/CD Workflows  
- `.github/workflows/quality.yml.template` - Comprehensive quality checks
- `.github/workflows/test.yml.template` - Test matrix (Python 3.9-3.13 × OS matrix)
- `.github/workflows/docs.yml.template` - Sphinx documentation building
- `.github/workflows/release.yml.template` - PyPI trusted publisher release

### Testing & Coverage
- `pytest.ini.template` - pytest configuration
- `.coveragerc.template` - coverage.py settings (85% threshold)
- `tox.ini.template` - Multi-environment testing

### Tool Configs
- `.ruff.toml.template` - Standalone ruff configuration
- `.bandit.yaml.template` - Security scanning configuration

### Documentation
- `docs/conf.py.template` - Sphinx configuration
- `docs/index.rst.template` - Documentation index

### Utilities
- `apply-python-quality.sh` - Script to apply templates to a project
- `MIGRATION_GUIDE.md` - How to adopt these tools
- `TOOL_VERSIONS.md` - Recommended tool versions

## Quality Standards

- **Coverage**: 85% target, 80% minimum (build fails below 80%)
- **Linting**: ruff with 25+ rule categories
- **Type Checking**: mypy strict mode
- **Security**: bandit HIGH severity enforcement
- **Formatting**: black (88 char), isort
- **Python Support**: 3.9-3.13

## Usage

```bash
# Copy templates to your project
cp build-tools/python/pyproject.toml.template myproject/pyproject.toml

# Edit placeholders
sed -i 's/{{PROJECT_NAME}}/myproject/g' myproject/pyproject.toml
sed -i 's/{{PACKAGE_NAME}}/myproject/g' myproject/pyproject.toml

# Or use the apply script
cd build-tools/python
./apply-python-quality.sh ../../myproject
```

## Version Format

FlossWare projects use **X.Y versioning** (not X.Y.Z):
- Examples: `0.1`, `0.2`, `1.0`, `1.1`, `2.0`
- PyPI fully supports this format
- Simpler version management
- Matches FlossWare build-tools standard (currently 2.0)

When using templates:
```python
# pyproject.toml.template
version = "{{VERSION}}"  # Use X.Y format: "0.1", "1.0", etc.
```
